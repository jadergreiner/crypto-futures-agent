## Tarefas de Implementação (GREEN Phase)

### TAREFA 1: Implementar Contrato de Auditoria no Provider

**Objetivo**: Enriquecer payload retornado por `TechnicalSignalInferenceProvider.infer()` com campos de auditoria.

**Campos obrigatórios** (adicionar ao retorno do provider):

```python
{
    # Existentes (preservar)
    "action": "OPEN_LONG" | "OPEN_SHORT" | "HOLD",
    "confidence": float,
    "size_fraction": float,
    "sl": float | None,
    "tp": float | None,
    "reason": str,
    "metadata": {...},
    
    # NOVOS (implementar)
    "origin": "RL_MODEL" | "FALLBACK",  # RL_MODEL se action_source='rl_action' e rl_fallback=False
    "contaminated": bool,              # True se action_source='signal_side' ou rl_fallback=True
    "baseline_comparative": {           # Dict com decisão alternativa
        "action": str,
        "confidence": float,
        "reasoning": str
    },
    "decision_id": str,                 # UUID imutável para idempotência
}
```

**Lógica de `origin`**:
- `origin = "RL_MODEL"` ⟺ `action_source == "rl_action"` ∧ `rl_fallback == False`
- `origin = "FALLBACK"` ⟺ `action_source == "signal_side"` ∨ `rl_fallback == True`

**Lógica de `contaminated`**:
- `contaminated = True` ⟺ `action_source != "rl_action"` ∨ `rl_fallback == True`

**Baseline comparative**:
- Manter a ação alternativa não executada (ex.: se RL decide LONG, baseline é signal_side action)

**Decision_id**:
- Gerar UUID4 para cada inferência ou reusar `model_input` hash se disponível
- Imutável — mesmo input deve gerar mesmo decision_id

**Onde implementar**: 
- Opção A (recomendada): Enriquecer em `TechnicalSignalInferenceProvider.infer()` antes de retornar
- Opção B: Enriquecer em `ModelInferenceService.infer()` após chamar provider e antes de `evaluate_model_decision_payload()`

### TAREFA 2: Persistir Campos de Auditoria em `model_decisions`

**Objetivo**: Garantir que campos de auditoria sejam salvos em `model_decisions.payload_json` sem alterar schema.

**Implementação**:
1. Modificar `core/model2/repository.py` para aceitar e persistir `origin`, `contaminated`, `baseline_comparative`, `decision_id` em `payload_json` como JSON aninhado
2. Garantir idempotência por `decision_id` — não sobrescrever registros com mesmo `decision_id`
3. Sem schema change — campos vivem dentro de `payload_json` (coluna TEXT/JSON existente)

**Exemplo de persistência**:
```python
model_decision = {
    "id": int(timestamp * 1000),
    "symbol": "BTCUSDT",
    "decision_timestamp": timestamp,
    "payload_json": {
        "action": "OPEN_LONG",

        # Novos campos

        "contaminated": False,
        "baseline_comparative": {...},
        "decision_id": "uuid-xxx",
    },
    "input_json": {...}
}
```

### TAREFA 3: Ajustar `operator_cycle_status` para Ler e Exibir `source`

**Objetivo**: Exibir `source` coerente no status (ex.: `source=modelo` vs `source=FALLBACK`).

**Implementação**:
